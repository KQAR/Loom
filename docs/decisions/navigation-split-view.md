# Why `MainView` is a plain `HStack`

> Moved out of `AGENTS.md` on 2026-08-07 (0.0.18), unedited. It is a **record**, not
> an instruction: what was tried, what it cost, and why the current shape is the
> shape. The invariant it produced lives in `AGENTS.md` § Known Issues, which links
> here — read that first; come here when you are about to re-open the question.

**`MainView` uses a plain `HStack` deliberately — never `NavigationSplitView`, and no longer `HSplitView`.** With live traffic + tail-follow, a sidebar category switch inside `NavigationSplitView` pays a quadratic AppKit KVO teardown across the row hosting views accumulated by scrolling: measured **8.7–16 s of main thread vs 143–224 ms** (61×) on the same view. Both it and `HSplitView` land on `NSSplitView`; only `NavigationSplitView`'s private pane glue stalls, so the defect is in the container, not split views or anything Loom does per row (all per-row work sums to ~18 ms). `HSplitView` was then dropped too, because a bare `NSSplitView` has no collapse semantics — no `isCollapsed`, so the sidebar could only be inserted and removed, which pops — and its divider here was already fixed and undraggable, so it was buying nothing. The collapse now animates the pane's **width** (300↔0, trailing-aligned + `.clipped()`, so it pushes out instead of squashing); the toolbar `sidebar.left` button (`.navigation` placement) and ⌃⌘S share one animated action. **The one bridge that would give AppKit's own sidebar — `NSSplitViewController` with a `.sidebar` split item, which brings the system drawer animation and the system `.toggleSidebar` toolbar item — was built, measured and rejected**: on macOS 26 that item is wrapped in an 8pt `NSContainerConcentricGlassEffectView` sitting **40pt off the window's top** (32pt titlebar + its own 8), placed by an AppKit constraint (`wrapper.top == card.top - 40`) that survives both a `frame` override and a change to its constant. A rounded inset card is not the flush sidebar DESIGN.md draws. Two more measured dead ends worth not re-walking: centring the status chip on the *content pane* (padding the `.principal` item stretches the macOS 26 shared-glass capsule by the same 300pt; hiding that shared background makes the toolbar draw a full-width backdrop), and removing the lighter band across the window top — that is macOS 26's scroll edge effect (`NSScrollPocket`, one per scroll view), untouched by `titlebarAppearsTransparent`, by hiding the titlebar backdrop, and by SwiftUI's `scrollEdgeEffectHidden`; AppKit's `NSScrollEdgeEffectStyle` is 26.1 and settable only on accessory controllers. It predates the animation work. Full two-round investigation record for the `NavigationSplitView` half (sample stacks, A/B matrix, lldb findings): [`docs/performance/navigation-split-view-kvo.md`](../performance/navigation-split-view-kvo.md); DESIGN.md § main-window records the container decision.
