When nothing shows up

A request you expected isn't in the table. These are the causes in the order worth checking, because several of them look identical from the outside.

1. The host isn't in the SSL scope

By far the most common. The scope is a whitelist, and a host you haven't named is relayed encrypted — which records no flow at all, so it looks exactly like a client that never ran. Open SSL Scope: the hosts Loom saw but couldn't read are listed there, and adding one is a click. See Decrypting HTTPS.

2. The client isn't going through Loom

Plenty of software ignores the system proxy — anything using its own HTTP stack, most notably Node's global fetch. Check with a request you control:

curl -x http://127.0.0.1:9090 http://example.com

If that lands and your app doesn't, the app isn't being proxied. Give it a reverse-proxy endpoint or point it at the SOCKS port.

3. Recording is paused

The dot in the console is yellow and the toolbar's record button reads "Start". Traffic is still flowing — Loom just isn't writing it down. An agent can pause recording too, so this can be true without you having done it.

4. A rule is dropping it

A drop from capture rule forwards the request normally and never records it. That is what it is for, but it means the traffic is genuinely working and genuinely invisible. The Rules panel counts the drops per rule — that counter is the only evidence.

5. The connection was refused

If a client connected and Loom turned it away — a SOCKS4 client on the SOCKS port, an HTTP request sent to the wrong listener — that is counted and reported rather than left silent. The console's alert channel and the proxy status both carry the count, so "nothing arrived" and "something arrived and was rejected" don't read the same.

Still nothing

  • The proxy didn't start. The main window says so plainly and offers to change the port — almost always another proxy already holding 9090.
  • The app pins its certificates. It will refuse Loom's certificate no matter what is trusted. Nothing to configure; that app can't be intercepted.
  • A phone can't reach this Mac. The Device tile goes orange when device capture is on but the network can't reach the listener — usually a Wi-Fi network with client isolation, or a firewall.

If you think you have found a real bug, the project's issue tracker is at github.com/KQAR/Loom/issues. Captures hold real credentials — export with redaction on, and check what you're attaching.
