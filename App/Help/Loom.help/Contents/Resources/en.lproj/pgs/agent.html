Loom Help

Handing it to an agent

This is what Loom is for. An AI agent can drive the whole debug loop — capture, change, replay, compare — while you watch from the console.

Connecting

In Claude Code:

claude plugin marketplace add KQAR/Loom
claude plugin install loom@loom

Then make sure the Loom app is running and restart Claude Code. Cursor works the same way — add KQAR/Loom as a plugin marketplace in its plugin settings.

The plugin doesn't launch or build anything; it just points the agent at the running app on http://127.0.0.1:9092/mcp. If the tools are unreachable, the app isn't running.

What it can do

Everything you can do from the window, and a few things you can't:

  • Read — list recent flows, read one in full, search headers and bodies, list devices, aggregate timings and error rates.
  • Wait — block until the request you're about to trigger actually arrives, instead of polling.
  • Write — replay with overrides, set rules, arm breakpoints and edit a held request, change the SSL scope, toggle the system proxy, create reverse-proxy endpoints, import and export HAR.
  • Compare — diff two flows and get the answer as data.

Things to say out loud, as examples:

  • "What did the app just call when I tapped login?"
  • "Replay that without the auth header and tell me what changed."
  • "Mock this endpoint to return a 500 and see how the app handles it."
  • "Point this API at staging."
  • "Why is this endpoint slow?"

How you stay in the loop

There is no approval prompt, on purpose — an agent that has to ask before every write can't close a loop. Two things replace it:

  • The control port is loopback only. It is a separate port from the proxy precisely so that turning on device capture, which binds the proxy to the whole network, never exposes the write-capable control plane to the Wi-Fi.
  • Every write is audited. The Audit panel in the sidebar lists each write tool call with its arguments and when it happened. Secrets in those arguments — certificate bundles, passphrases — are redacted.

And because the agent is a second writer, the window and console re-read the engine after every write rather than trusting their own copy: if an agent turns recording off, the dot goes yellow.

The plugin and the app update independently. If the agent's description of a tool doesn't match what the app actually offers, one of the two is behind — the agent is told to check and say so, and the live tool list is always the truth.
